# 5月20日心态复盘

## 今日主题：从“难以着手”到“第一个可演示版本”

### 里程碑

今天，我的战棋战斗系统终于跑通了第一个从自由探索到入战、再到回合轮转的完整闭环。这是一个可以在控制台里清晰观察所有状态流转的、勉强可以演示的版本。

### 当前进度

- **双轮转战斗队列**：完成。玩家与敌人共用行动队列，按固定顺序轮转。单位死亡后从队列移除，队列为空时自动触发脱战。
- **战斗管理器**：完成。通过事件总线管理全局战斗状态（Exploration ↔ Combat），协调入战判定、队列轮转、脱战清理的全流程。
- **入战脱战控制**：完成。基于 NavMesh 路径距离的入战判定，支持战斗进行中新敌人动态增援并正确插入队列。全部敌人死亡或玩家脱离最大距离后脱战。

### 已跑通的完整流程

1. **自由探索**：WASD 控制玩家移动，相机跟随。
2. **入战触发**：敌人进入检测范围，NavMesh 路径校验通过，触发 BattleEnter，相机切换为战斗跟随。
3. **回合轮转**：玩家行动 → 结束回合 → 敌人自动行动 → 结束回合 → 循环。
4. **动态增援**：战斗中新增敌人走近后自动加入队列，在下一回合登场。
5. **脱战退出**：全部敌人死亡，触发 BattleExit，相机恢复探索模式。

### 心态复盘：绕过完美主义陷阱

这个系统的设计文档，我在两周前就已经写好了。但面对那份庞大而精密的设计，我瘫痪了整整好几天（其实我git中缺少的4月都可以算是瘫痪，其实不止几天）。  
我反复在想：是不是要先搭好完美的事件架构？是不是要在第一步就融入速度队列？是不是应该先把 NavMesh 校验的所有边界情况都考虑到？  
我决定先做。  
就如同我跟我朋友讲述这个决定的时候我说：“既然时间不够了，既然整个过于庞大，就如同造车一样，我大不了不要车壳了，引擎能带动轮子转就是成功”（实际上我到现在其实也没完成半点车壳也就是UI或者其他表现层，但之后肯定还是要加）  
然后就磕磕绊绊重新开始捡起来了这个项目，实际上一切比我想象中顺利的多，做起来了真的就什么都不怕了，虽然过程中还是不可少的很多困难很多bug，甚至不少bug自己都啼笑皆非（比如今天才发现我挂在角色上的脚本设定的触发距离很短，覆盖了我代码内的设定，搞得我当个逻辑bug测试了很久，又比如战斗中无法插入新入战敌人的bug，准确来说应该是需求变更？）。  
**但总而言之先动手，比在那里摊着空想更重要。开始做了之后回望，才会发现其实一切都并不如想象中可怕。**
