# 开发日志：2025-05-14

## 今日目标

编写 `BattleManager`，将 `EventBus` 和 `BattleQueue` 串联，建立战斗生命周期管理。

## 完成内容

### 1. `BattleManager.cs` 实现

- **字段**：`battleQueue`（回合队列实例）、`unitObjMap`（ID→GameObject映射）、`isBattleActive`（战斗状态标志）。
- **核心方法**：
  - `StartBattle(List<(int id, float speed, GameObject obj)> participants)`：初始化单位映射，创建队列，桥接四个关键事件到 `EventBus`，订阅 `TurnEnd` 和 `UnitDied` 外部事件，先发布 `BattleStart` 再初始化队列（保证顺序正确），最后激活战斗标志。
  - `EndBattle()`：反桥接事件，取消外部事件订阅，清理映射和队列，发布 `BattleEnd`，重置标志。支持重复调用安全（`StartBattle` 开头检测旧战斗并先清理）。
- **桥接方法**：使用具名方法（`OnRoundStartBridge` 等）实现 `BattleQueue` → `EventBus` 的翻译，确保可取消订阅，避免内存泄漏。
- **外部事件回调**：`OnExternalTurnEnd` 和 `OnExternalUnitDied`，受 `isBattleActive` 保护，防止战斗外误操作。

### 2. `EventBus.cs` 配合

- 已具备完整的有参/无参事件支持，桥接无缝。

### 3. 问题修复与优化

- 修复事件触发顺序：`BattleStart` 在 `InitQueue` 之前，避免其他模块无法获取战斗上下文。
- 添加重复调用保护：`StartBattle` 先调用 `EndBattle` 清理旧战斗。
- 全部事件使用具名方法注册/反注册，确保配对正确。

## 当前架构概览

```
外部输入（UI/敌人AI）→ EventBus 发布 TurnEnd、UnitDied
    ↓
BattleManager 监听 → 调用 BattleQueue 方法
    ↓
BattleQueue 触发 C# 事件 → BattleManager 桥接 → EventBus 广播
    ↓
其他模块（UI、相机、角色控制器）通过 EventBus 响应
```

## 遇到的知识点

- C# 事件订阅与取消的配对要求：匿名 lambda 不能取消，必须使用具名方法或委托变量。
- 事件触发顺序对系统状态的影响：`BattleStart` 应先于回合初始化，确保订阅者收到正确的上下文。
- 循环依赖的避免：`BattleQueue` 纯逻辑类不依赖 `EventBus`，由 `BattleManager` 桥接，保持可测试性。
