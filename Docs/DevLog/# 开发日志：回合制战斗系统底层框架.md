# 开发日志：回合制战斗系统底层框架

## 2025年5月13日

### 背景

现有项目为自由探索模式，使用直接引用和单例通信，耦合严重。为了扩展回合制战斗系统，决定先构建解耦的底层通信基础设施和回合逻辑核心。

### 已完成工作

#### 1. 事件总线 `EventBus.cs`

- **实现基于枚举事件ID的发布/订阅机制**，支持带参数（`Action<T>`）和无参数（`Action`）两种委托类型。
- **核心设计**：使用 `Dictionary<E_EventType, Delegate>` 存储委托，利用 `Delegate.Combine` / `Delegate.Remove` 管理多播委托，自动清理空委托的键，防止内存泄漏。
- **类型安全**：在发布时通过 `as` 转换并检查类型，不匹配时输出警告，便于调试。
- **枚举事件ID**：定义了 `E_EventType` 枚举（当前包含 `TurnStart`, `RoundStart` 等战斗相关事件），未来可扩展。

#### 2. 回合队列管理器 `BattleQueue.cs`

- **双队列轮转模型**：`nowRoundQueue`（当前回合未行动单位）和 `readyQueue`（已行动或等待下一回合的单位，按速度降序排列）。
- **速度降序插入算法**：`InsertSorted` 使用 `List.FindIndex` 找到第一个速度小于待插入单位的索引，实现稳定排序（同速保持原始顺序）。
- **事件驱动生命周期**：
  - 初始化后触发 `OnRoundStart` 和 `OnUnitTurnStart`。
  - 单位行动完成（`OnTurnEnd`）后，自动推进到下一个单位，或当队列为空时触发 `OnAllUnitsActed` 并调用 `FinishRound` 切换到下一回合。
  - 支持动态添加/移除单位，并正确处理队首死亡或离场的情况。
- **纯逻辑类**：不依赖任何 Unity 类型，可单独进行单元测试。

#### 3. 修复与优化

- 修复 `InitQueue` 中空队列判定的逻辑错误（`&&` 替代 `||`）。
- 修复 `RemoveUnit` 中队首死亡后队列变空的索引越界风险。
- 添加 `GetNowOrder()` / `GetReadyOrder()` 返回只读拷贝。
- 添加 `BattleQueueClear()` 并在清理时触发 `OnBattleEnd` 事件。

### 关键设计决策

- **为什么使用枚举而非字符串作为事件ID？**
  - 提供编译期类型检查，避免拼写错误，IDE 自动补全更友好。
- **为什么不直接将 `BattleQueue` 事件挂载到 `EventBus`？**
  - 保持 `BattleQueue` 的纯逻辑可测试性。外部（如 `BattleManager`）负责将它的 C# 事件桥接到 `EventBus`。
- **双队列轮转 vs 单队列重新排序？**
  - 双队列模型更直观：每个单位每回合行动一次，行动后移至准备队列，回合结束时交换。易于理解且边界情况清晰。

### 当前状态

- 两个核心模块（`EventBus` 和 `BattleQueue`）已完成，并通过初步逻辑验证（尚未进行单元测试）。
- 下一步：编写单元测试并集成到 Unity 场景中，通过 `BattleManager` 将二者连接，驱动角色行动。

### 后续计划

1. 编写 `BattleManager`（MonoBehaviour），创建 `BattleQueue` 实例，将其事件转发到 `EventBus`。
2. 利用现有 `SelectEvent` / `ClickSelector` 模拟回合制操作：选择角色 → 点击地面移动 → 点击“结束回合”按钮触发 `OnTurnEnd`。
3. 测试完整回合循环：多个角色轮流行动，回合自动交替，单位死亡移除队列。
4. 根据测试结果调整 `BattleQueue` 的边界处理和事件触发时机。
