# 开发日志：2026-05-19

## 今日目标

实现入战/脱战检测系统，使玩家在自由探索阶段靠近敌人时自动触发战斗，并确保与现有 `EventBus`、`BattleQueue`、`BattleManager` 无缝衔接。

## 完成内容

### 1. 新增脚本

- **`BattleProximityDetector.cs`**  
  每个玩家角色挂载此组件，默认禁用。通过监听 `SelectEvent.OnCharacterSelected` 切换激活状态（只有当前主控角色的触发器工作）。  
  - 动态添加 `SphereCollider`（IsTrigger），实现粗筛半径（20米）。  
  - 每秒协程遍历范围内所有敌人，调用 `EnemySensor.CheckEngageDistance` 进行 NavMesh 路径精确判断。  
  - 收集满足条件的敌人，合并所有玩家单位，调用 `BattleManager.Instance.StartBattle` 启动战斗。  
  - 修复：`PerformDetection` 中 `readyEnemies` 为空时直接返回，避免启动空战斗。

- **`EnemySensor.cs`**  
  每个敌人挂载，复用 `NavMeshPath` 缓存，计算自身到目标的 NavMesh 路径长度，返回是否 ≤ 入战阈值（8米）。  
  - 处理路径不可达、部分可达的情况。  
  - `NavMesh.SamplePosition` 对玩家和自身采样，确保目标点在 NavMesh 上。

- **`UnitIdentity.cs`**  
  单位标识组件，提供静态列表 `playerUnits` 供全局收集。包含 `unitID`、`speed`、`isPlayer` 字段。  
  - 在 `OnEnable/OnDisable` 中自动维护 `playerUnits` 列表。

### 2. 修复的问题

- **`BattleProximityDetector`**  
  - `OnTriggerEnter/Exit` 中 `otherSensor` 字段改为局部变量，避免潜在覆盖。  
  - `DetectionRoutine` 协程在 `yield return` 后增加 `isActive` 再次判断，防止停用后额外执行一次。  
  - `OnDisable` 中先停止协程再取消事件订阅，保证执行顺序安全。

- **`BattleManager`**  
  - 确认单例已实现（`Awake` 中 `Instance = this`，`DontDestroyOnLoad`）。  
  - 补充 `EndBattle` 中 `battleQueue` 空引用防护（检查 `battleQueue == null` 直接返回）。  
  - 监听 `SceneManager.sceneUnloaded` 事件，清空 `UnitIdentity.playerUnits` 静态列表，避免跨场景残留。

- **`EnemySensor`**  
  - `NavMeshPath` 状态判断使用 `PathComplete`，排除 `PathPartial` 和 `PathInvalid`。  
  - 路径长度计算前确认 `corners.Length >= 2`。

### 3. 事件对接

- `BattleProximityDetector` 通过 `BattleManager.Instance.IsBattleActive` 防止战斗进行中重复触发入战检测。  
- `BattleManager` 已暴露 `public static BattleManager Instance` 和 `public bool IsBattleActive`，其他脚本可直接引用。

## 当前问题/潜在风险

- **战斗结束后的状态恢复**：战斗结束后，主控角色的 `BattleProximityDetector` 仍保持激活状态（因为 `SetActive(true)` 未在战斗中被重置）。这是预期的，但需注意若主控角色在战斗中死亡，战斗结束后需通过 `SelectEvent` 重新选中一个新的主控，其检测器才会激活。  
- **敌人死亡后引用清除**：若敌人在 `enemiesInRange` 中死亡且未触发 `OnTriggerExit`，会导致集合中残留无效引用。需在 `EnemySensor.OnDestroy` 中通知所属的 `BattleProximityDetector` 移除（可通过事件或手动在 `BattleManager.RemoveUnit` 中处理）。当前未实现，后续迭代。
