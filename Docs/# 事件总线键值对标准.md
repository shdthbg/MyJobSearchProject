# 事件总线键值对标准(新规采用枚举代替ID，现已放弃此标准)

所有事件均通过全局静态类 `EventBus` 发布/订阅，事件键使用 `public static readonly string` 常量集中定义，避免拼写错误。

## 1. 原有交互事件（现有代码桥接使用）

| 事件键常量 | 参数类型 | 用途说明 |
| ----------- | ---------- | ---------- |
| `CHARACTER_SELECTED` | `GameObject` | 角色或单位被选中 |
| `CHARACTER_DESELECTED` | `GameObject` | 取消选中 |
| `MOVE_COMMAND` | `MoveCommandArgs` | 对单位下达移动指令 |

`MoveCommandArgs` 结构：

```csharp
public struct MoveCommandArgs {
    public GameObject unit;
    public Vector3 target;
}
```

---

## 2. 回合制系统核心事件

| 事件键常量 | 参数类型 | 用途说明 |
| ----------- | ---------- | ---------- |
| `BATTLE_START` | `BattleStartArgs` | 战斗状态开始，传递参战单位列表等信息 |
| `BATTLE_END` | 无（`Action`） | 战斗结束，返回探索状态 |
| `TURN_START` | `GameObject` | 某一角色/敌人开始其回合，参数为行动单位对象 |
| `TURN_END` | `GameObject` | 当前行动单位结束回合 |
| `ENEMY_SPOTTED` | `EnemySpottedArgs` | 敌人发现玩家，用于激活判定 |
| `BATTLE_QUEUE_CREATED` | `List<GameObject>` | 混合行动队列生成完毕，供UI显示顺序 |
| `ACTION_POINT_CONSUMED` | `ActionPointArgs` | 行动点消耗通知（含单位及剩余点数） |

**自定义参数类型建议定义：**

```csharp
// 可根据实际需要扩展
public struct BattleStartArgs {
    public List<GameObject> participants;
    // 可补充战场信息
}

public struct EnemySpottedArgs {
    public GameObject enemy;
    public GameObject targetPlayer;
    public float pathLength;
}

public struct ActionPointArgs {
    public GameObject unit;
    public int remaining;
}
```

## 3. 系统扩展备用事件（未来重构时启用）

| 事件键常量 | 参数类型 | 用途说明 |
| ----------- | ---------- | ---------- |
| `CAMERA_TARGET_CHANGED` | `Transform` | 相机跟随目标发生变化 |
| `UI_UPDATE_REQUEST` | 无（`Action`） | 统一请求UI刷新，替代轮询 |
| `GAME_STATE_CHANGED` | `GameState` | 全局游戏状态（探索/战斗）切换通知 |

`GameState` 为枚举类型，至少包含 `Explore` 与 `Battle` 两个值。

---

## 4. 使用约定

- **订阅**：在 `MonoBehaviour.OnEnable` 中调用 `EventBus.Subscribe<T>(eventKey, handler)`。
- **解订**：在 `MonoBehaviour.OnDisable` 中调用 `EventBus.Unsubscribe<T>(eventKey, handler)`。
- **发布**：`EventBus.Publish<T>(eventKey, args)` 或无参的 `EventBus.Publish(eventKey)`。
- 参数类型必须与实际订阅/发布时指定的泛型类型严格一致，建议所有自定义参数类型定义为轻量级 `struct` 或不可变 `class`。
- 调试阶段可开启事件总线内置日志开关，追踪事件流向。

此标准覆盖了当前回合制系统开发所需的所有交互，并预留了未来系统级重构的接口，可在后续开发中随时补充新事件键。
